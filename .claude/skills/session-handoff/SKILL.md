# 세션 저장 · 이어받기

클라우드 세션은 끝나면 컨테이너가 사라지고, 기기마다 파일도 따로다. **저장소(GitHub)에 push된 것만 남는다.** 그래서 저장 위치는 그 프로젝트의 **할 일 파일 하나**다. 새 파일을 늘리지 않는다.

할 일 파일 찾는 순서: 프로젝트 CLAUDE.md가 정한 파일, 다음으로 README가 가리키는 진행 파일(예: `05_운영/다음할일.md`, `05_진행상황.md`), 없으면 저장소 루트 `TASKS.md`.

## A. 저장 모드 (기기를 옮기기 전, 세션을 끝내기 전, 언제든)
1. 끝난 일은 할 일 파일에서 지운다(취소선으로 남기지 않음). 결정이나 정정이 생겼고 프로젝트에 기록 파일이 있으면 거기에 1줄.
2. 할 일 파일 **맨 위**에 `## 이어서 할 곳`을 쓴다. 이전에 쓴 것은 덮어쓴다.
   - 마지막으로 한 일 (한 줄)
   - 지금 작업 중인 곳: 파일 경로, 문서 링크나 ID, 브랜치, 돌고 있던 작업(워크플로 실행 번호 등)
   - 다음 한 걸음: 바로 시작할 수 있게 구체적으로
   - 내 결정이 필요한 것, 내가 눈으로 확인할 것
   - 이미 정한 규칙은 복사하지 말고 어느 파일 몇 절에 있는지만
3. 커밋하고 push한다. 그 프로젝트의 브랜치 규칙을 따르고, 충돌하면 멈추고 알린다. push가 거절되면 fetch 후 merge해서 다시 올린다. 원격과 로컬이 같은지 확인한다. **push되지 않은 채로 끝내지 않는다.** 저장소가 없는 대화면 어디에 둘지 한 번만 묻는다.
4. 답은 "내 결정이 필요한 것 / 바꾼 것 / 알아낸 것"과 **다음 세션에 붙여 넣을 멘트**(6줄 이내)로 끝낸다.
   > [프로젝트 이름] 이어서 할게. [할 일 파일]의 `이어서 할 곳`부터 읽고 진행해줘. [오늘 정한 것 1~3개] [내가 정해서 말해줄 것]

## B. 이어받기 모드 (새 세션의 첫 요청이 "이어서 할게")
1. `git log --oneline -5`와 할 일 파일의 `이어서 할 곳`부터 읽는다. 다른 파일은 필요할 때만 연다.
2. 첫 답에서 내 결정이 필요한 것과 내가 볼 것을 먼저 알리고, 바로 할 수 있는 다음 한 걸음부터 시작한다. 이미 정한 것은 다시 묻지 않는다.
3. 그 프로젝트에 맞는 스킬이 있으면 그 스킬을 쓴다.

## 하지 않는 것
- 대화를 요약해 파일을 늘리기
- 정하지 않은 것을 확정해서 적기 (미정은 결정 대기에 둔다)
